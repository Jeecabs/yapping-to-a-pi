# Wispr Flow macOS parity research

Researched 2026-10-11 against Wispr and Apple primary sources. This is a product reference and implementation checklist, not a claim that these features are implemented. The target remains both a Pi extension and a standalone Mac app, with on-device speech recognition and original yapping to a pi branding.

## Personalization and editing

| Priority | Capability | Documented Wispr behavior | On-device implementation requirement |
| --- | --- | --- | --- |
| P1 | Cleanup and backtracking | Removes fillers and clear self-corrections, formats lists, supports spoken punctuation and line/paragraph breaks. Contextual uses of words such as “actually” remain intact. Formatting failure pastes the original. History can switch between original and formatted text. [Smart Formatting](https://docs.wisprflow.ai/articles/5373093536-how-do-i-use-smart-formatting-and-backtrack) | Speech recognition alone does not establish this behavior. Add optional local text processing, keep original text, and test that names, numbers, negation and code survive. |
| P1 | Dictionary | Words, phrases and explicit misspelling corrections. Desktop fields allow 60 characters. Corrections match whole words without regard to case, prefer the longer overlapping phrase and retain saved spelling. Proper nouns and specialist terms can be learned from user edits. [Dictionary](https://docs.wisprflow.ai/articles/4052411709-Teach-Flow-your-words-with-the-dictionary) | Separate vocabulary entries from literal replacement rules. Manual replacements are feasible locally; passive learning from edits is a separate feature. |
| P1 | Snippets | Spoken trigger expands alone or within a sentence. Desktop trigger limit is 60 characters, expansion limit 4,000 including formatting. Supports bold, italic, links and lists, with plain-text fallback in unsupported destinations. [Snippets](https://docs.wisprflow.ai/articles/5784437944-create-and-use-snippets) | Plain-text expansion is only partial parity. Rich-text paste, overlap rules, search, editing and deletion also matter. |
| P1 | Writing styles | Categories: Personal, Work, Email, Other, selected from app or website. Formal uses capitalization and punctuation; Casual uses less punctuation; Very Casual adds lowercase for Personal; Excited adds exclamations for the other categories. Email also formats greetings and sign-offs. Notices describe styles as English-only. [Styles](https://docs.wisprflow.ai/articles/2368263928-how-to-setup-flow-styles) | A single global style does not match category styles. Keep style selection separate from recognition locale and let unsupported languages retain their original text. |
| P1 | Context awareness | Reads nearby text and app or website identity; recognizes visible names and adjusts spacing/casing. Current docs say text-based context, without screenshots. Standard secure fields, financial apps and certain sensitive fields are excluded. Context is discarded after each dictation. [Context](https://docs.wisprflow.ai/articles/4678293671-feature-context-awareness) | Read limited Accessibility context with an off switch. Exclude secure fields. Do not keep context in history or allow captured text to become instructions for the local language model. |
| P1 | Languages | More than 100 languages; one detected language per dictation. Users choose one, several or automatic detection. Regional variants control spelling or script. Language settings apply to the next dictation. [Languages](https://docs.wisprflow.ai/articles/3191899797) | Populate speech locales from Apple at runtime. An explicit locale picker is useful but does not equal automatic multilingual recognition or Wispr's language coverage. |
| P1 | Command Mode | Optional and off by default, activated with Fn+Ctrl. Hold, dictate a natural instruction, release. Uses current field and selected text to edit or draft; results bypass ordinary dictation formatting. Desktop search commands open Perplexity. Empty fields cannot support text edits. [Command Mode](https://docs.wisprflow.ai/articles/4816967992-How-to-use-Command-Mode) | Treat spoken editing as a separate operation with captured selection, an explicit local-model requirement, stale-selection protection and undo. | P1 | Transforms | Opt+1 Polish, Opt+2 Prompt Engineer, Opt+O comparison; eight custom prompt slots. Accepts 1 to 1,000 words, using selection, readable field or a recent dictation. [Transforms](https://docs.wisprflow.ai/articles/8068950331-how-to-use-transforms-beta) | A cleanup checkbox is not transform parity. Provide explicit actions and a reviewable result; handle model limits without losing text. Translation must be separately gated by supported languages. |
| P1 | History and privacy | Searchable entries, transcript copy, original/edited views, deletion and retention controls. Normal, 24-hour and never-store policies are separate from model improvement and cloud storage. Wispr still processes dictation in the cloud when model improvement is off. [Navigation](https://docs.wisprflow.ai/articles/5096240724-navigating-the-wispr-flow-app-desktop-ios-and-android), [Privacy controls](https://docs.wisprflow.ai/articles/9609615338-private-cloud-sync-and-data-sharing-preferences-in-wispr-flow) | Provide local text retention and clear deletion. | P2 | Import and developer context | Dictionary CSV and snippet JSON import, at most 3 MB and 1,000 accepted entries. IDE context can preserve code symbols and filenames. ## Apple constraints

1. **Speech and rewriting are different capabilities.** `SpeechAnalyzer` with `SpeechTranscriber` provides on-device transcription. Assets are installed through `AssetInventory`; hardware and locale support require runtime checks. This does not itself provide command editing, summaries or Wispr's cleanup. [Apple speech overview](https://developer.apple.com/videos/play/wwdc2025/277/), [SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber)

2. **Do not promise SpeechTranscriber vocabulary biasing.** Apple's `AnalysisContext.contextualStrings` documentation specifically describes `DictationTranscriber`, recommends brief phrases, and limits the total to 100. The `SpeechTranscriber` documentation does not document this capability. Given this project's required engine, use explicit text replacements and label them accurately unless recognition biasing is independently verified. [Contextual strings](https://developer.apple.com/documentation/speech/analysiscontext/contextualstrings)

3. **Local rewriting is conditional.** Foundation Models requires an eligible device, enabled Apple Intelligence and downloaded models. Check `SystemLanguageModel.default.availability`, handle every unavailable reason and preserve ordinary dictation when rewriting cannot run. Speech availability and language-model availability are separate checks. [Model availability](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel), [Unavailable reasons](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel/availability-swift.enum/unavailablereason)

4. **Locale support must be checked independently.** `supportsLocale(_:)` and `supportedLanguages` describe local language-model support. Prompts, output languages and generated schemas all count as model inputs; an unsupported language can fail generation. Language support changes with OS/model versions. Never advertise Wispr's 100+ languages for this app without evidence from supported speech and rewriting paths. [Foundation Models languages](https://developer.apple.com/documentation/foundationmodels/supporting-languages-and-locales-with-foundation-models)

5. **macOS 26 has a small text budget.** Apple's documented context window is 4,096 tokens, including instructions, prompts, schemas and generated output. Long cleanup, translation and meeting summaries require separate bounded sessions or another explicit handling strategy. Catch context errors and retain the original. Newer SDK documentation includes version-specific APIs, so check deployment availability before using token-count or context-size methods. [Context window](https://developer.apple.com/documentation/technotes/tn3193-managing-the-on-device-foundation-model-s-context-window)

6. **A local model is not cloud-model quality parity.** Apple describes the device model as suitable for summarization, extraction and classification, not broad world knowledge or advanced reasoning. Its response quality, timing and preservation of dictated meaning need evaluation on the shipping model. Use fresh sessions for independent dictations and offer original-text recovery. [Foundation Models overview](https://developer.apple.com/videos/play/wwdc2025/286/)

## Explicit differences required by this repository

- Keep speech on device after asset installation. Wispr's cloud speech path is a reference workflow, not a dependency.
- Never save recordings. Wispr's 14-day audio playback, WAV export and audio-based retry therefore cannot be mirrored under the current rule. Text history and text reprocessing remain possible. [Wispr recovery](https://docs.wisprflow.ai/articles/2503460374)
- Never submit a Pi prompt automatically. Wispr offers an optional spoken “press enter” action; that action must not override this project's editable-text guarantee. [Wispr hands-free commands](https://docs.wisprflow.ai/articles/6391241694-use-flow-hands-free)
- Preserve the existing Pi controller/process seam, quiet idle behavior and session shutdown cleanup. Standalone app lifecycle is separate from Pi lifecycle.
- Use original app artwork and icons while matching the useful interaction patterns.

## Acceptance evidence needed

### Current local implementation

The agreed scope is macOS personal dictation. Meeting notes, team accounts, cloud sync and task integrations are outside scope. The desktop app is branded **computer, listen**.

Implemented: hold and hands-free dictation, a compact movable bar, text insertion with focus checks, local text history, manual dictionary entries, plain-text snippets, global and per-app writing styles, selected-text voice editing, and custom text transforms. Speech uses Apple Speech on device. Cleanup and transforms require Apple Intelligence.

Remaining differences include rich-text snippets, automatic dictionary learning, arbitrary shortcut bindings, website-specific styles and automatic language detection. These are not claimed as feature parity. Audio history and automatic prompt submission are deliberately excluded by the project requirements.

The user confirmed that the startup fix reaches Listening. Automated tests cover process delivery, gestures, storage, text rules, positioning and the PCM meter. Cross-app insertion and model output quality still need broader manual acceptance testing.

### Manual acceptance checklist

These checks are implementation recommendations derived from the findings above:

- Verify hold, toggle, double-tap, cancel, shutdown and late-result behavior without triggering microphone permission in automated tests.
- Manually verify insertion at a cursor and over a selection in native fields, browsers, a code editor and a terminal. Include focus changes while processing, secure fields, paste failure and preservation of the clipboard.
- Verify panel behavior with multiple displays, Spaces, a full-screen app, hidden Dock, reduced motion and VoiceOver.
- Evaluate names, code, punctuation, negation, numbers, lists, self-corrections, snippets and overlapping dictionary entries. Compare original and transformed text.
- Exercise unavailable speech assets, unsupported locales, disabled Apple Intelligence, local-model failures, cancellation while processing and long-text limits.
- Check the app icon at Dock, Finder and small menu bar sizes. Distinguish a built bundle, a launched app, a manually verified dictation flow and a signed/notarized release.

## Source caveats

Wispr documentation changes quickly. Live article bodies were preferred over search snippets, which contained older behavior. Its Mac installation guide says Input Monitoring is needed only for standalone Caps Lock shortcuts, while its hands-free guide describes it more broadly. Determine the actual permission requirement from the chosen shortcut implementation and test it on supported macOS versions. This research reviewed public documentation, not a signed-in Wispr installation or a pixel-level recording of every screen.
